# 실시간 세션 번역 릴레이

세션에서 속기사가 타이핑하거나 OpenAI가 실시간 전사한 내용을 즉시 여러 언어로
번역해, 참석자가 자기 언어 페이지만 열어 두고 세션을 따라갈 수 있게 하는 웹 애플리케이션.

**자체 호스팅 전용**이다. 사람 입력과 AI 실시간 전사 중 하나를 세션마다 고른다.

기본 언어는 한국어 · 베트남어 · 태국어 · 싱할라어 넷이고, 관리자 화면에서
**언어를 더 추가할 수 있다** — 130여 개 목록에서 고르면 화면 문구까지 번역 엔진으로
번역해 채운다.

---

## 요구 사항

**Node.js 22.13.0 이상** (권장: 24 LTS)

이 앱은 Node 내장 `node:sqlite` 를 쓴다. 네이티브 모듈을 빌드하지 않아
설치 사고가 없는 대신, 이 모듈은 **v22.13.0부터** 플래그 없이 쓸 수 있다.
그보다 낮으면 `--experimental-sqlite` 가 필요하다.

```bash
node -v          # v22.13.0 이상인지 확인
nvm install 24   # 낮다면
```

## 시작하기

```bash
npm install
cp .env.example .env.local     # 값을 채운다 (아래 참고)
npm run dev
```

`http://localhost:3000` 에서 뜬다. 같은 네트워크의 다른 기기에서는
`http://<이 컴퓨터의 IP>:3000` 으로 접속한다.

### Windows 데스크톱 앱

`release/Live Conference Translation Setup 0.1.0.exe`를 설치해 실행하면 서버와
관리자 화면이 함께 열린다. 첫 실행 때 생성된 관리자 비밀번호를 복사해 로그인한다.
상단 **설정 → Cloudflare 공개 URL 만들기**를 누르면 별도 설치나 계정 없이 임시 HTTPS
주소가 생기며, 세션 화면의 복사·새 창·QR 주소도 그 공개 주소로 자동 전환된다.

Quick Tunnel은 테스트·현장 공유용 임시 기능이다. 앱을 종료하거나 터널을 끄면 주소가
사라지고, 다음 실행 때 새 주소가 발급된다.

### 최소 설정

`.env.local` 에 최소한 이 세 가지가 필요하다.

```bash
ADMIN_PASSWORD=원하는_비밀번호
SESSION_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")
GOOGLE_TRANSLATE_API_KEY=발급받은_키
```

나머지는 `.env.example` 에 설명이 있다.

## 쓰는 순서

1. `/admin/login` 에서 비밀번호로 로그인
2. 세션을 만들 때 입력 방식을 고르면 필요한 페이지가 **자동 생성**된다
   - 속기사 입력: 입력 N개 + 출력 N개 + 통합 조회 1개
   - AI 실시간 전사: 음성 수집 1개 + 출력 N개 + 통합 조회 1개
3. 세션 대시보드에서 URL 을 복사해 배포한다
   - 속기사에게 → `/in/<토큰>`
   - 참석자에게 → `/out/<토큰>`
   - 무대 뒤 모니터 → `/all/<토큰>` (모든 언어 동시)
4. 속기사가 타이핑 → 나머지 언어로 번역되어 각 페이지에 실시간 도착
5. 세션이 끝나면 대시보드에서 종료. 로그는 언어별로 걸러 `.txt` 로 받는다

참석자용 `/out/<토큰>`과 통합 조회 `/all/<토큰>`은 저대역폭 전용 경량 HTML로
제공한다. React 런타임·전역 웹폰트·Tailwind 자산을 받지 않고 WebSocket만 연결하며,
재연결 뒤 빠진 문장도 자동 보충한다.

## AI 실시간 전사

세션 생성 화면에서 **AI 실시간 전사**를 고르면 세부 페이지에 언어별 음성 수집 URL이
생긴다. 각 언어 속기사가 입력 페이지를 쓰듯 해당 언어의 마이크 페이지를 열 수 있고,
확정 원문은 다른 모든 언어로 번역된다. 원문과 같은 언어 출력에는 원문이 그대로 표시된다.

- OpenAI 키가 필요하며 전사는 `gpt-live-transcribe`를 쓴다.
- 마이크 권한 때문에 `localhost`가 아닌 기기에서는 **HTTPS 공개 URL**로 열어야 한다.
- 언어별로 캡처 기기 하나가 활성화된다. 서로 다른 언어 마이크는 동시에 쓸 수 있다.
  같은 언어의 다른 기기는 기존 기기가 중지되거나 활성권이 만료된 뒤 시작할 수 있다.
- 부분 인식 문장은 수집 화면에만 보이고, 확정 문장만 저장·번역된다.
- 원음은 서버나 SQLite에 저장하지 않는다.

## 언어 추가하기

`/admin` 세션 생성 폼의 **언어** 라벨 옆에 버튼이 둘 있다.

- **`+` — 언어 추가.** 검색창에 `japanese` 든 `일본어` 든 `にほんご` 든 `ja` 든 치면
  찾힌다. 고른 뒤 UI 문구를 번역할 엔진을 지정하고 추가하면, 화면 문구 90여 개를
  그 엔진으로 번역해 저장한다. 추가한 언어는 세션 언어로도, 우상단 표시 언어
  드롭다운으로도 바로 쓸 수 있다.
  - 번역에 실패한 문구는 **그 문구만** 한국어로 나온다. 화면이 비지 않는다.
  - 고른 엔진이 그 언어를 지원하지 않으면 미리 알려 준다.
  - 기본 4개 언어와 이미 세션에 쓰인 언어는 지울 수 없다.
- **`⚙` — 문구 수정.** 기계 번역이 어색한 문구를 직접 고친다. 한국어 원문을 나란히
  보여 주고, 되돌리기로 원래 값으로 복귀할 수 있다. 「다시 번역」을 눌러도
  **손으로 고친 문구는 보존된다.**

새 문자의 글꼴은 기기에 맡긴다. 번들에 들어 있는 건 기본 4개 언어용 Noto 4종뿐이라,
크메르어·미얀마어 같은 문자는 기기에 글꼴이 없으면 네모(□□□)로 보일 수 있다.

## 번역 엔진

세션을 만들 때 주 엔진과 선택 폴백 엔진을 고른다. 기본값은 Google 번역이고
폴백은 사용하지 않는다.

| 엔진 | 성격 | 지원 언어 | 한국어 | 베트남어 | 태국어 | 싱할라어 |
| --- | --- | :-: | :-: | :-: | :-: | :-: |
| `google` | 기계 번역, 기본값 | 130여 개 | ✅ | ✅ | ✅ | ✅ |
| `deepl` | 기계 번역 | 공식 API에서 자동 확인 | ✅ | ✅ | ✅ | ❌ |
| `openai` | LLM 번역 | 제한 없음 | ✅ | ✅ | ✅ | ✅ |

`openai` 를 고르면 엔진 옆에 **언어모델 드롭다운**이 함께 나온다. 지난 조회 목록을
즉시 보여 주고 관리 화면을 열 때마다 계정의 최신 목록으로 갱신한다. 고른 값은 전역
설정으로 저장된다.

주 엔진이 언어를 지원하지 않거나 키가 없을 때만 선택한 폴백 엔진을 쓴다.
폴백을 고르지 않았다면 해당 언어 번역은 실패로 표시된다.
DeepL 지원 여부는 `/v2/languages` 응답을 24시간 캐시해 자동으로 갱신한다.

어느 엔진이 실제로 처리했는지는 번역 레코드마다 저장된다.

### LLM 엔진을 쓰는 이유

기계 번역은 문장 단위로만 본다. 세션에는 "그건", "아까 말씀하신" 같은 표현이
계속 나오는데 앞 발언을 모르면 풀 수 없다. `openai` 엔진은 직전 발언 몇 줄을
문맥으로 함께 넘겨 대명사와 용어를 맞춘다. 대신 지연과 비용이 더 크다.

## 구조

```
server.ts              커스텀 Node 서버 (HTTP + WebSocket)
src/
  app/
    api/               라우트 핸들러
    page.tsx           진입점
  lib/
    db.ts              SQLite 연결 + 스키마
    repo.ts            모든 SQL
    pipeline.ts        입력 → 저장 → 번역 → 배포
    translate/         엔진 3종 + 폴백 라우터
    realtime/          WebSocket 허브와 프로토콜
    languages.ts       언어 코드 → 이름(Intl.DisplayNames 파생)
    i18n-builtin.ts    기본 4개 언어 UI 문구 (클라이언트 안전)
    i18n.ts            DB 오버레이를 얹는 문구 해석기 (서버 전용)
    ui-translate.ts    추가한 언어의 UI 문구 기계 번역
    auth-core.ts       서명·검증 (커스텀 서버와 공유)
    auth.ts            Next 쿠키 연동
  hooks/
    use-appearance.ts  테마·글자 크기 (localStorage)
```

### 왜 커스텀 서버인가

입력 페이지에 속기사가 여러 명 들어와 서로 작성 중인 문장을 봐야 한다.
이 흐름이 양방향이라 WebSocket 이 필요한데, Next.js 라우트 핸들러만으로는
업그레이드를 받을 수 없다. 자체 호스팅이라 제약이 없어 HTTP 서버를 직접 띄우고
Next 를 그 위에 얹었다.

**문장 전송(submit)만 HTTP POST 로 남겨 두었다.** 저장을 동반하는 동작이라
검증 실패나 세션 종료를 상태 코드로 분명히 돌려주는 편이 낫다.

### 데이터

SQLite 파일 하나(`data/meetings.db`)에 전부 들어간다. 백업은 이 파일을 복사하면 된다.
`data/` 는 git 에서 제외되어 있다.

## 보안 — 초안 범위에서 감수하는 것

기본 서버 자체에는 **HTTPS/TLS가 없다.** 사람 입력 모드는 신뢰할 수 있는 로컬
네트워크에서 쓸 수 있지만, AI 음성 수집은 브라우저 정책상 HTTPS 프록시가 필요하다.

이 전제에서 실제로 성립하는 위험:

- 같은 네트워크에서 트래픽을 보면 **세션 내용과 관리자 비밀번호가 평문으로 보인다**
- 페이지 URL 토큰도 평문으로 오간다 — 네트워크를 엿볼 수 있으면 누구나 들어올 수 있다
- Cloudflare 같은 HTTPS 프록시로 접속하면 관리자 쿠키에는 자동으로 `Secure` 가 붙는다

지켜야 할 운영 규칙:

- 공용 Wi-Fi 에 올리지 않는다
- 세션이 끝나면 종료 처리해 입력을 막는다
- **인터넷에 노출한다면 Cloudflare Tunnel 같은 TLS 프록시를 거치는 것이 최소 조건이다.**
