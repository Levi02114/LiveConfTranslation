# 실시간 회의 번역 릴레이

회의에서 속기사가 타이핑한 내용을 즉시 여러 언어로 번역해, 참석자가 자기 언어
페이지만 열어 두고 회의를 따라갈 수 있게 하는 웹 애플리케이션.

**로컬 네트워크 자체 호스팅 전용**이다. 음성 인식은 없다 — 입력은 사람이 친 텍스트다.

지원 언어: 한국어 · 베트남어 · 태국어 · 싱할라어

---

## 요구 사항

**Node.js 22.13.0 이상** (권장: 24 LTS)

이 앱은 Node 내장 `node:sqlite` 를 쓴다. 네이티브 모듈을 빌드하지 않아
설치 사고가 없는 대신, 이 모듈은 **v22.13.0부터** 플래그 없이 쓸 수 있다.
그보다 낮으면 `--experimental-sqlite` 가 필요하다.

```bash
node -v          # v22.13.0 이상인지 확인
nvm install 24   # 낮다면
```

## 시작하기

```bash
npm install
cp .env.example .env.local     # 값을 채운다 (아래 참고)
npm run dev
```

`http://localhost:3000` 에서 뜬다. 같은 네트워크의 다른 기기에서는
`http://<이 컴퓨터의 IP>:3000` 으로 접속한다.

### 최소 설정

`.env.local` 에 최소한 이 세 가지가 필요하다.

```bash
ADMIN_PASSWORD=원하는_비밀번호
SESSION_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))")
GOOGLE_TRANSLATE_API_KEY=발급받은_키
```

나머지는 `.env.example` 에 설명이 있다.

## 쓰는 순서

1. `/admin/login` 에서 비밀번호로 로그인
2. 회의를 만들면 언어별 페이지가 **자동 생성**된다
   - 언어 N개 → 입력 N개 + 출력 N개 + 통합 보기 1개 = **2N + 1**
3. 회의 대시보드에서 URL 을 복사해 배포한다
   - 속기사에게 → `/in/<토큰>`
   - 참석자에게 → `/out/<토큰>`
   - 무대 뒤 모니터 → `/all/<토큰>` (모든 언어 동시)
4. 속기사가 타이핑 → 나머지 언어로 번역되어 각 페이지에 실시간 도착
5. 회의가 끝나면 대시보드에서 종료. 로그는 언어별로 걸러 `.txt` 로 받는다

## 번역 엔진

회의를 만들 때 고른다. 기본값은 Google 번역이다.

| 엔진 | 성격 | 한국어 | 베트남어 | 태국어 | 싱할라어 |
| --- | --- | :-: | :-: | :-: | :-: |
| `google` | 기계 번역, 기본값 | ✅ | ✅ | ✅ | ✅ |
| `deepl` | 기계 번역 | ✅ | ✅ | ✅ | ❌ |
| `openai` | LLM 번역 | ✅ | ✅ | ✅ | ✅ |

### ⚠️ DeepL 은 싱할라어를 지원하지 않는다

공식 지원 언어 목록에 없다. 엔진을 DeepL 로 두어도 **싱할라어 방향은 자동으로
Google 번역으로 넘어간다.** 따라서 싱할라어를 쓰는 회의라면
`GOOGLE_TRANSLATE_API_KEY` 도 함께 설정해야 한다.

어느 엔진이 실제로 처리했는지는 번역 레코드마다 저장된다.

### LLM 엔진을 쓰는 이유

기계 번역은 문장 단위로만 본다. 회의에는 "그건", "아까 말씀하신" 같은 표현이
계속 나오는데 앞 발언을 모르면 풀 수 없다. `openai` 엔진은 직전 발언 몇 줄을
문맥으로 함께 넘겨 대명사와 용어를 맞춘다. 대신 지연과 비용이 더 크다.

## 구조

```
server.ts              커스텀 Node 서버 (HTTP + WebSocket)
src/
  app/
    api/               라우트 핸들러
    page.tsx           진입점
  lib/
    db.ts              SQLite 연결 + 스키마
    repo.ts            모든 SQL
    pipeline.ts        입력 → 저장 → 번역 → 배포
    translate/         엔진 3종 + 폴백 라우터
    realtime/          WebSocket 허브와 프로토콜
    i18n.ts            4개 언어 UI 문구
    auth-core.ts       서명·검증 (커스텀 서버와 공유)
    auth.ts            Next 쿠키 연동
  hooks/
    use-appearance.ts  테마·글자 크기 (localStorage)
```

### 왜 커스텀 서버인가

입력 페이지에 속기사가 여러 명 들어와 서로 작성 중인 문장을 봐야 한다.
이 흐름이 양방향이라 WebSocket 이 필요한데, Next.js 라우트 핸들러만으로는
업그레이드를 받을 수 없다. 자체 호스팅이라 제약이 없어 HTTP 서버를 직접 띄우고
Next 를 그 위에 얹었다.

**문장 전송(submit)만 HTTP POST 로 남겨 두었다.** 저장을 동반하는 동작이라
검증 실패나 회의 종료를 상태 코드로 분명히 돌려주는 편이 낫다.

### 데이터

SQLite 파일 하나(`data/meetings.db`)에 전부 들어간다. 백업은 이 파일을 복사하면 된다.
`data/` 는 git 에서 제외되어 있다.

## 보안 — 초안 범위에서 감수하는 것

**HTTPS/TLS 를 쓰지 않는다. 신뢰할 수 있는 로컬 네트워크 전용이다.**

이 전제에서 실제로 성립하는 위험:

- 같은 네트워크에서 트래픽을 보면 **회의 내용과 관리자 비밀번호가 평문으로 보인다**
- 페이지 URL 토큰도 평문으로 오간다 — 네트워크를 엿볼 수 있으면 누구나 들어올 수 있다
- 관리자 쿠키에 `Secure` 를 걸 수 없다

지켜야 할 운영 규칙:

- 공용 Wi-Fi 에 올리지 않는다
- 회의가 끝나면 종료 처리해 입력을 막는다
- **인터넷에 노출한다면 리버스 프록시로 TLS 를 씌우는 것이 최소 조건이다.**
  그때 `src/lib/auth.ts` 의 쿠키 `secure` 를 `true` 로 바꿔야 한다
